Chess Swarm — Orchestration Brief

Goal, architecture, and live progress of the multi-agent build→review→test loop driving the chess-game repo.

Mission

Execute the feature roadmap in RECOMMENDATIONS.md using a continuous build → review → test loop staffed by three separate agents (builder, reviewer, tester), coordinated by an orchestrator. Every task is logged to a Kanban board and tracked on the canvas until it reaches DONE.

The Loop

1. ClaimOrchestratorClaim task from boardBACKLOG → BUILDING
2. BuildBuilderImplement + selftest + wire package.jsonBUILDING
3. VerifyOrchestratorIndependent node --check / wiring / Gate-4—
4. ReviewReviewerCorrectness, Gate-4, coverage → APPROVE/CHANGESIN_REVIEW
5. TestTesternpm run check + Gate-4 → PASS/FAILIN_TEST
6. CommitOrchestratorCommit + flip boardDONE

Guiding invariants

  • Gate-4: ui.js (and all new modules) must never call makeMove( or createInitialBoard( — the referee is authoritative.
  • Every feature ships a matching *-selftest.js, wired into both test:unit and lint (grep count = 2).
  • No build step, no framework, no bundler; no external npm deps (bcrypt/passkey forbidden — use crypto.scrypt).
  • Final gate for any change: npm run check exits 0.

Tech stack

  • Local-first vanilla JS — no build step, no framework, no bundler.
  • Node.js referee backend (server.js → referee-service.js) with SSE + JSON snapshot/journal.
  • SQLite archive (node:sqlite) with JSON-file fallback.
  • Plain <script> client modules; CommonJS + window.* fallback everywhere.
  • Zero external runtime deps (crypto is Node built-in).
